**Repository:** `pranshavsingh/driver-complain-demo`  
**Target Environment:** Hostinger KVM 4 VPS, Ubuntu Linux, MySQL 8.0  
**Target Collation:** `utf8mb4_0900_ai_ci`  
**Standardized Migration:** `apps/api/prisma/migrations/20261106120000_init_mysql/migration.sql`

## 1. Audit Findings: `utf8mb4_unicode_ci` vs `utf8mb4_0900_ai_ci`

During the M8.1 baseline generation via `prisma migrate diff --from-empty --to-schema-datamodel`, Prisma CLI emitted `DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci` across all 28 `CREATE TABLE` statements. However, the production architecture for the Hostinger KVM 4 VPS specifies MySQL 8.0, where `utf8mb4_0900_ai_ci` is the server's default collation.

### Collation Comparison

| Dimension | `utf8mb4_unicode_ci` | `utf8mb4_0900_ai_ci` (Selected Standard) |
|---|---|---|
| **Unicode Version** | Unicode 5.2.0 (Legacy, 2009) | Unicode 9.0.0 (Modern UCA, 2016) |
| **Case Sensitivity** | Case-insensitive (`ci`) | Case-insensitive (`ci`) |
| **Accent Sensitivity** | Mostly accent-insensitive | Explicitly accent-insensitive (`ai`) |
| **MySQL 8.0 Native Default** | No (legacy compatibility only) | **Yes (default collation for `utf8mb4`)** |
| **Performance** | Slower due to older collation weight tables | Fast, optimized implementation in MySQL 8.0 |
| **Emoji & Symbol Sorting** | Incomplete Unicode 9 collation | Full Unicode 9.0 standard ordering |
| **Unique Constraint Behavior** | Collapses case variants (`'ADMIN'` == `'admin'`) | Collapses case and accent variants (`'ADMIN'` == `'admin'`) |

## 2. Baseline Standardization

All 28 table creation clauses in `apps/api/prisma/migrations/20261106120000_init_mysql/migration.sql` have been standardized to:

```sql
DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

Zero occurrences of `utf8mb4_unicode_ci` remain in active migrations. Archived PostgreSQL migrations in `apps/api/prisma/migrations_postgresql_archive/` remain unmodified.

## 3. Application Identifier Normalization Audit

Relying solely on database collation for business rules is an antipattern; application boundaries must normalize inputs before querying or storing. The codebase audit verified:

1. **Employee IDs (`User.employeeId`):**
   - Normalized via `.trim().toUpperCase()` in `createUser`, `updateUser`, and `checkAvailability`.
   - Unique index `User_employeeId_key` prevents case-variant collisions in MySQL.
2. **Email Addresses (`User.email`):**
   - Normalized via `.trim().toLowerCase()` in `createUser`, `updateUser`, and `checkAvailability`.
   - Unique index `User_email_key` enforces uniqueness.
3. **Driving License (`Driver.licenseNumber`):**
   - Normalized via `.trim().toUpperCase()` in `createUser`, `updateUser`, and `checkAvailability`.
   - Unique index `Driver_licenseNumber_key` prevents duplicate licenses.
4. **Vehicle License Plates (`Vehicle.plateNumber`):**
   - Normalized via `.trim().toUpperCase()` in `createVehicle` and `updateVehicle`.
   - Unique index `Vehicle_plateNumber_key` prevents duplicates.
5. **Chassis Number / VIN (`Vehicle.vin`, `Vehicle.chassisNumber`):**
   - Normalized via `.trim()` at creation and update.
   - Unique index `Vehicle_vin_key` prevents duplicates.
6. **Complaint Numbers (`Complaint.complaintNo`):**
   - System-generated deterministically: `DC-${year}-${counter}`.
   - Unique index `Complaint_complaintNo_key`.
7. **Operating Sites (`OperatingSite.code`, `OperatingSite.name`):**
   - `code` normalized via `.trim().toUpperCase()`.
   - `name` normalized via `.trim()`.

Under `utf8mb4_0900_ai_ci`, queries using `contains`, `startsWith`, and `equals` (with `mode: 'insensitive'` removed) execute as case-insensitive and accent-insensitive operations without requiring database-specific query flags.
